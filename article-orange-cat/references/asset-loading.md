# Visual Reference Preflight · 橘猫机制说明书

## 设计目标

本 Skill 的目标不是“画一只戴帽子的橘猫”，而是 **保持用户已定稿的整体视觉 DNA**。文字提示不是风格基准；未经视觉输入验证，不得声称和参考图一致。

## Gate A — 定位并验证素材（缺一不可）

必需的三张原始视觉样本：

- assets/preview.png — 主视觉锚点：白底线稿、固定 IP、动作与批注
- assets/examples/example-old-vs-new.png — 对照机制构图
- assets/examples/example-x402-bazaar.png — 单机制交互构图

优先从已安装 Skill 的本地 assets/ 路径读取。若 Skill 运行时不能暴露二进制图片，可从拥有权限的仓库/文件存储取原始图像字节到本地，再执行检查；但是只获取到 URL/文件列表/Base64 字符串并不算“看到图”。

若能使用 Python 3（无需第三方依赖）：

    python3 scripts/validate_assets.py

在仓库根目录执行：

    python3 article-orange-cat/scripts/validate_assets.py

失败退出码为 2。若其中有 FAIL，直接停止生成；不得跳过、伪造检查结果或用其它画风替代。没有 Python 时，使用具有实际图像解码能力的可用工具完成同等检查。

## Gate B — 视觉读取与风格比对

必须把 **通过解码的图像** 显示给视觉模型，并在开始前确认：

- 固定 IP 的黑针织帽、圆黑墨镜、黑高领、脸形与比例
- 黑色细线手绘语言与白底留白密度
- 橙色流程、蓝色批注、红色风险的职责与使用量
- 道具密度、画面层级、插画质感
- 对照与单机制场景如何保持一致画风

“我读了 SKILL.md / README / 看见了 URL”不等于完成 Gate B。

## Gate C — 生图引用

使用能够 **实际将参考图片传入** 生图工具的方式（图像编辑、image-to-image、参考图输入等）；保持可用的固定 IP 与风格，只调整当前文字对应的动作与道具。

在只支持纯文字的环境里，不能保证复刻已定稿母版。应直说当前环境做不到严格复现，**不要先生成别的风格再交付**，也不要临时写 SVG 充当原画。

## Gate D — 风格探针与验收

先生成第一张独立机制图，将成图与主参考和至少一张 example 对照：

1. 第一眼是白底手绘机制说明书，不是彩色海报/漫画/信息图；
2. 猫的固定 IP 与样图一致且正在操作道具；
3. 留白、黑线、颜色语义、文字密度都相近；
4. 只解释一个机制，最多 2–3 个主要道具；
5. 无明显中文乱码，插入位置准确。

任何硬失败，针对偏差定向重试一次；仍失败则中止，并告知用户未达到风格基准。不生成更多不合格图片。
