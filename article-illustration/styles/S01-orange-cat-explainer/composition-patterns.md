# S01 Composition Patterns

这些是构图思路，不是固定模板。每次优先根据当前文章重新发明隐喻。

## Pattern A · 输入 → 处理 → 输出

适合：模型、系统、API、筛选、自动化。

画法：左侧材料 → 中间猫操作 → 右侧结果。

## Pattern B · 卡点 / 风险

适合：权限、封号、依赖、瓶颈、异常。

画法：猫在闸门、路障、绳结、插头、管道接头等位置处理问题。

## Pattern C · 从复杂到简单

适合：MVP、删功能、抽模块、降低复杂度。

画法：一侧复杂堆积，猫只取出少量核心组件，另一侧形成可运行的小闭环。

## Pattern D · 闭环

适合：复盘、循环、持续优化、现金流。

画法：用箭头、纸带或管道形成简单回路，猫在关键节点检查、盖章或补料。

## Pattern E · 隐喻落地

适合：原文已经有强视觉比喻。

画法：把文字隐喻转成真实物理动作，例如“小船先下水”。

## Pattern F · 揭开隐藏结构

适合：“表面看起来 X，实际内部是 Y”。

画法：猫掀开盖子、拆开机器或打开剖面，露出内部机制。

## Pattern G · 筛选 / 分流

适合：1000 → 20、粗筛 → 精筛、普通请求 → 高价值请求。

画法：猫把大量输入倒进筛子/分拣机，只保留少数重点。

## Hard rule

如果需要 5 个以上模块才能讲清，先重新抽象认知任务，不要继续往图里塞东西。
